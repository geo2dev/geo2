# Release Notes 5.6

## Release Date

Hub: 

2026-10-12

Mobile app: 

2026-10-20

## New Features

------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| AI Assistant: POD information and stop reordering | The **AI Assistant** has been expanded with new capabilities for reviewing Proof of Delivery information and changing the order of stops and breaks within a route.You can now ask the AI Assistant questions about order PODs, for example **“*Does order #001 have a POD?”***, ***“Is order #001 delivered?”***, or ***“Show me order #001 POD.”*** The assistant can provide information such as whether a POD is available, the number of PODs, POD status, recorded date and time, driver name, and whether photos or a signature are attached or still pending. You can also ask broader operational questions, such as ***“How many collections do we have left to complete today?”***The AI Assistant can now also reorder stops and breaks within a route without removing and recreating them. For example, you can ask ***“Move the break after stop #10,” “Make stop #3 first,” “Move stops #2 and #3 to the end,”*** or **“*Move the second stop after the sixth one.”*** Breaks can also be moved based on time, for example ***“Move the break after 1 PM.”*** In this case, the assistant uses the planned stop times and places the break after the stop closest to the requested time. |
| Mobile app: New Currency and Vehicle costs settings | A new **Currency** option is available under **Settings → Display preferences**, allowing you to select the currency used for route cost calculations. The default currency is automatically selected based on your environment's country, but it can be changed to any supported currency. Two new optional fields are also available under **Settings → Vehicles** when creating or editing a vehicle:- **Cost per distance unit** — specify how much it costs to operate the vehicle per mile or kilometre, depending on the distance unit selected in Settings.- **Cost per hour** — specify the vehicle's hourly operating cost.These rates are used to automatically calculate route costs based on the actual distance travelled and the route duration. Both fields are optional, so you can configure either one or both depending on how you want to calculate your route expenses. All costs are displayed in the currency selected in Settings. |
| Mobile app: Route completion statistics and cost calculation | The new **Route completed** screen provides a detailed summary of route performance, including the number of completed, successful, and failed stops, along with a visual progress bar showing their statuses.The **Route cost** section displays the actual tracked distance, distance cost, time cost, total cost, and average cost per stop, calculated using the rates configured for the assigned vehicle. If vehicle rates have not been configured yet, they can be added directly from this screen to calculate the route cost.The same statistics and cost breakdown are also available on the **Route view** page for completed routes, making it easy to review route performance and expenses at any time. After completing a route, users can quickly navigate to their next planned route or start planning a new one. |

| Hub/Mobile app: Italian language support | Geo2 Hub and mobile app are now available in **Italian**. If your browser or device language is set to Italian, Geo2 will automatically use Italian by default. You can also change the interface language manually at any time using the **language selector in the Profile menu** in the top-right corner of Hub or **in Settings** in the mobile app. |
| Hub: Routes Calendar view customization and area grouping | The **Routes → Calendar view** has been updated with new customization and grouping options to make route planning more flexible. You can now configure which information is displayed on Calendar route cards under **Settings → Routes → Calendar route card layout**. Choose from details such as planned start and end time, distance, duration, number of stops, peak weight and volume, driver, participants, vehicle, area, and route status. Displayed fields can also be reordered using drag-and-drop, while the route key remains permanently visible. This allows you managing many routes to keep Calendar cards compact, while users who need more operational detail can display additional information directly on the card without opening the route.Calendar view now also supports grouping routes **By area**, in addition to the existing **By driver** and **By vehicle** options. The new grouping option is available in both **Daily and Weekly** Calendar views, making it easier to review and compare route schedules across different geographical areas. |
| Hub: Switching between List, Table, Calendar, and Map on Routes page | The existing **Map view** is now available directly within **Routes page**, alongside the **List, Table, and Calendar** views. This makes Routes the single place for reviewing and managing routes in different formats without navigating to a separate page. You can select one or more routes using checkboxes in **List or Table view** and then switch to **Map view** to visualize the same selection. If no routes are selected, Map view opens in an empty state. From there, you can add routes to the map or work with **unassigned orders**, following the same approach as the previous standalone Map view. All existing Map view functionality remains available, including displaying multiple routes with route colors, viewing and selecting stops on the map, moving stops between routes, adding orders to routes, and adding or managing route breaks. |
